# 检测报告与复测

## 读取与映射

从实际报告识别平台、时间、稿件版本、指标名称、检测范围、显示值和标记段落。
缺失字段写“未识别”，不猜测算法、版本或分母。
疑似 AI 内容比例、AI 风险概率和文本重复率是不同指标，不能混比。
HTML 只解析内容，不执行脚本；颜色结合图例解读。OCR 后回看原图确认百分数、符号和小数点。
部分章节的检测不能写成全文比例。用实际段落及章节位置匹配标记，重复或版本不一致时注明歧义。
修改标记段落需读取上下文，单句抽出检测的结果不能代替全文复测。

## 比较条件

同一平台核对指标名称、范围、语言、检测版本和设置。未知项说明限制，不假装已控制。
记录实际报告来源及稿件文件名；可计算文件 SHA-256，避免混淆候选稿。
平台逐一比较，不能平均。各平台必须使用相同的原稿和同一份候选稿，才能汇总是否均下降。
缺少结果、只给区间或显示“低于20%”时保留标签，不转换成精确数值。

## 输出表

| 平台 | 原稿显示值 | 同一最终改稿显示值 | 变化（百分点） | 状态 | 报告依据 |
|---|---|---|---|---|---|
| 实际平台 | 原报告值 | 复测值 | 改后减改前 | 下降／持平／上升／已为零／尚不可比 | 文件与时间 |

下降10个百分点与下降10%不同，默认使用百分点。
不把分数解释为真实创作过程中 AI 所占的比例。

## 可选脚本

`scripts/compare_reports.py` 只计算已经核实的输入，不访问网站、不调用检测器、不产生检测分数。
输入 JSON 顶层 `pairs` 为数组，每项包含：

- `platform`：实际平台名，数组内唯一。
- `before_version`、`after_version`：稿件版本标识；所有平台的对应版本分别一致。
- `before_pct`、`after_pct`：报告精确显示值，0至100；缺失或只有区间用 null。
- `comparable`：核对比较条件后填 true；未核清填 false。
- `before_report`、`after_report`：实际报告来源，不得编造。
- `note`：范围、检测版本或其他限制。

解析实际技能目录与用户文件位置后使用绝对路径；以下相对路径只展示参数：

```bash
python scripts/compare_reports.py --input report-pairs.json --out report-comparison.json
```

脚本不验证报告真伪或 `comparable` 是否填写正确。只有所有项目可比、来源与分数齐全、稿件版本一致且逐一严格下降，才返回“本次已测试平台均下降”。
这不代表未测平台或今后更新的检测器会下降。

## 后续修订

以复测标记为依据局部修改，不追求固定改动量。
某平台改善、另一平台变差时报告实际冲突并保存版本，不以平均值掩盖回升。
没有单一稿件在全部平台同时改善时，不宣称全部达标。
原稿为0只能维持0，不能计为严格下降；负数检测比例无效。
保留通过内容核对的候选稿，达到目标后停止；连续两轮无可验证改善时报告进展，等待新材料或继续指令。
