# 改写后的反向审读

本模块基于上游内容修改适配，来源及修改记录见 [来源清单](../../../third_party/manifest.json)。许可见 [LICENSE](../../../third_party/fidelity-review/LICENSE)。适用于中文正文和论文英文摘要。

## 先查含义

重新提取改稿的主张，与原文逐条对应，检查是否增加或遗漏事实、名称、数值、日期、引语、引用、排序和同时发生关系。尤其检查分句、并列改写和去修饰后的信息损失。

1. 改文新增的每一条内容能否指回原稿？仅有“合理”不足以成立。
2. 原文独有的事实、条件和反例是否还在？不要只检查文字是否更顺。
3. 相关与因果、可能与确定、部分与全部是否仍有区别？保留有意义的否定对照。
4. 同一个数字是否仍属于原来的对象和指标？是否把先后关系改成同时发生？
5. 引文是否仍支持原来的主张？不把未注明来源的内容改写成看似已经有出处的结论。

## 再查表达

连续阅读段落，修复修改造成的新重复、断裂或过度口语化。必要时围绕原段的中心重新组织，不再换一个同义词机械修补。没有新问题时停止，不为满足某个改动比例反复改。

用户给出作者旧稿时，可参照其句法、衔接、标点习惯；论文中只使用已提供的判断，不添加私人的幽默、感受、经历或自我修正故事。

英文摘要按内容使用正式学术英语，不强制改主动语态，不破坏技术复合词或连字符，不改量纲、数字、符号、缩写和引文。英文和数字的字体按原稿及用户明确要求处理，不能因风格检查改变格式。

## 交付前的闭环

- 各段及全文长度满足用户约束；超限要调整或明确说明实际冲突。
- 原稿、接受全部修订后的正文、净稿和 HTML 改文逐段一致地对应；拒绝本次修订可还原原文。
- 受保护内容和原格式均有实际核对记录。未检查的项目不得标记为通过。
- 正文只呈现论文内容；编辑过程、原文疑点与修改原因放在批注或报告中。
- 无真实复测只说“已完成改写，降分效果未验证”。本地规则命中数量减少不代表检测比例下降。
